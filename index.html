LatchQ: Latching onto Hot-Cache Query Interactions for KV Cache Quantization

Anonymous authors

Query evidence in the hot cache

The KV cache grows as a language model processes more tokens. Quantization makes it smaller. But the best numerical reconstruction is not always the one that best preserves attention.

Recent keys already spend time in a full-precision hot cache. During that window, subsequent queries attend to them. Those interactions reveal which keys are used and which channels are sensitive to error.

LatchQ turns that observation window into evidence for better clipping. QTrace summarizes the interactions. QClip uses the summary to choose a quantization range, preserving the baseline bit allocation, storage format, and cache schedule.

In the paper’s analysis, clipping choices based on hot-cache observations agree with a future-query oracle in 63% of evaluated decisions. At 2,048 tokens, LatchQ reduces KIVI-2’s NLL gap to FP16 by approximately 64%. [§2.2]

Method

01Observe & accumulate

QTrace

Measure sensitivity to quantization.

For the same query, quantized keys can produce different attention. QTrace estimates this sensitivity from the interactions observed while keys are still in the hot cache.

Attention-weighted query energy accumulates into Hd, a compact statistic for each key and channel.

The QTrace statistic
Hd[h,i,c] = ∑r, t ∈ Eᵢ a(r)t,i (q(r)t,c)²d

Here a is original attention, q is the observed query, and d is the head dimension. Query heads r share KV head h; Eᵢ contains observed subsequent queries. The statistic is computed once and reused across candidates.

02Evaluate & select

QClip

Select the argmin. Then quantize.

QClip scores 25 clipping candidates using reconstruction error weighted by Hd. It keeps the candidate with the smallest score.

That single choice determines how the key tiles become 2-bit codes, with a shared scale and offset.

The selection objective
arg minℓ, u∑i ∈ Bg wh,i,c (kh,i,c − k̂h,i,c)²

Selection is performed for each KV head, group, and channel. The weights combine QTrace evidence with a small positive floor. Scale and offset are stored in FP16.

What stays the same

  • Bit allocation
  • Storage format
  • Cache schedule

Abstract

KV cache quantization reduces the memory footprint of large language model (LLM) inference, but minimizing reconstruction error alone may fail to preserve attention behavior. Although future queries are unavailable at quantization time, keys can interact with subsequent queries while residing in the full-precision hot cache. Motivated by this observation, we introduce LatchQ, which uses these observed interactions to guide key clipping while preserving the baseline bit allocation. QTrace accumulates attention-weighted query energy for each key and channel, preserving differences in observed key usage and channel sensitivity. QClip leverages this evidence to select shared clipping ranges by minimizing interaction-weighted reconstruction error. Our method preserves the baseline storage format and cache schedule without extending hot-cache residency. Our analysis reveals 63% agreement between clipping range selections based on hot-cache observations and those based on future queries. Furthermore, LatchQ achieves the highest average LongBench scores among evaluated KV quantizers at 3.0 and 2.25 bits per dimension (bpd). It also outperforms the baseline quantizer on reasoning and code generation.
